# Engagement workflow design and execution plan

User approved all seven review recommendations, in order, followed by publication. Preserve static vanilla JavaScript, IndexedDB, Interval branding, private Hugging Face hosting, no runtime dependencies, no Docker and no paid services. Commander defaults below make the approved scope concrete.

1. Complete printed reports with every original evidence field and all mission guidance; retain safe text rendering. Verify print has distinct root cause, input path, prerequisites and mitigations.
2. Import confirmations require complete structured review and a substantive decision note (20 characters); incomplete current imports downgrade to unresolved. Frozen historical data with incomplete confirmation must reject rather than silently alter the hash. Preserve existing valid historical snapshot hashes exactly.
3. Use BroadcastChannel change hints plus focus refresh detection, explicit refresh preserving drafts, and fresh reads before printing current reports. Notifications contain only assessment IDs, not evidence. Never overwrite an unsaved dialog.
4. Add a five-hat workbook: one entry per selected role, owner, planned/in-progress/complete status, evidence reference, expected/observed results and review decision. Complete requires evidence, observed result and decision. Assessment revision CAS guards edits; fields are bounded/redacted and backed up/exported/snapshotted.
5. Add continuation: atomically check source revision and record capacity, create a fresh linked assessment with new finding IDs/revisions, preserved current evidence/tracking/business fields, no old snapshots/history, and a provenance entry. Source stays unchanged even at 200 events. Historical snapshots remain in the source. Parent ID/revision are provenance, not access control.
6. Add bounded analyst-written executive summary, business impact and prioritized recommendations; CAS guarded and present in Markdown/print/snapshots. Add client-filtered cross-assessment confirmed remediation view with owner/status/overdue filters and assessment links. Client labels remain organizational.
7. Show assessment count, approximate serialized record bytes, optional origin usage/quota estimate, event/snapshot/size warnings, last backup export initiated time (never claim file saved), and a recovery guide. Metadata failures are nonfatal.

Shared engine schema: optional `workbook` array of {role,owner,status,evidence,expected,observed,decision}; `delivery` {executive_summary,business_impact,recommendations}; `continuation` {parent_id,parent_revision}. For old snapshot canonical validation, omit missing new fields so hashes remain compatible. Normalize live records with safe defaults. APIs: PATCH /api/assessments/:id/workbook body {expected_revision,entry}; PATCH /api/assessments/:id/delivery body {expected_revision,delivery}; POST /api/assessments/:id/continue body {expected_revision}. Returns {assessment}. workspaceStatus() returns counts and approximate bytes, optional usage/quota (unavailable as null).

Ownership: backend owns local.js/test_local.cjs; frontend owns app.js/style.css/both HTML entries; commander owns browser tests, docs, packaging, verification and publication. Backend adds test-first stages 2,4,5,6,7, frontend implements stages 1,3,4,5,6,7 in interface order; no recursive agents.

Acceptance: fresh full Node/publisher/browser suites; legacy snapshots retain hashes; malformed imports and stale CAS leave records unchanged; continuation works at history cap and races cannot exceed capacity; complete workbook fields and reports round-trip; cross-tab warning preserves drafts, fresh print reads; recovery failures never block saved records; keyboard/narrow/wide screenshots.
