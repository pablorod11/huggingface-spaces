# Library roles and boundaries

This register explains the intended library allocation for the Gradio application. Dependency presence is not evidence that an algorithm was run, validated, or useful. The UI capability report and run exports must identify availability and actual selected estimators. The pinned `requirements.txt` and recorded runtime versions govern reproducibility; official documentation's moving `stable` versions may differ from those pins. Official references checked 25 October 2026.

- **Gradio:** input components, callback execution, charts and download presentation. Use the tested Gradio 6 version in both root README `sdk_version` and requirements. Uploads execute server-side; cache and file-serving controls are part of deployment verification. Official [Spaces integration](https://huggingface.co/docs/hub/spaces-sdks-gradio) was inspected. Direct Gradio migration/file-access guide retrieval failed; compatibility requires runtime evidence.
- **pandas:** CSV parsing, date columns and tabular reports. `read_csv` accepts diverse inputs, so this app should restrict it to the uploaded local file, enforce size/schema limits, reject nonfinite/nonpositive closes and validate dates. Do not offer arbitrary URL reads. [Official read_csv API](https://pandas.pydata.org/docs/reference/api/pandas.read_csv.html).
- **NumPy:** vectorized features, simulation, matrices and stable linear algebra. `lstsq`, `svd`, `eigh`, rank and determinant operations support the mathematical lab; matrix conditioning and finite inputs still need explicit checks. Use seeded generators for repeatable demos. [Official linear-algebra reference](https://numpy.org/doc/stable/reference/routines.linalg.html).
- **Plotly:** interactive calibration, distribution and forecast figures. Local HTML export can embed Plotly.js; a CDN option instead requires network access. Displaying training performance is not holdout validation. [Official HTML export guide](https://plotly.com/python/interactive-html-export/).
- **Matplotlib:** static figures and downloadable reports where the app exposes them. Headless deployment should use an appropriate noninteractive backend and close figures. The [official backend page](https://matplotlib.org/stable/users/explain/backends.html) returned no extractable body during this pass; its detailed contents were not inspected.
- **scikit-learn** (import `sklearn`): standardized pipelines, regularized linear models, probability metrics, isolation forest and classical ML challengers. Fit preprocessing on training data only. Isolation scores are not crash probabilities. Never accept uploaded pickle/joblib estimators: pickle-based persistence can execute arbitrary code. The [official persistence guide](https://scikit-learn.org/stable/model_persistence.html) discusses this risk and compatibility constraints.
- **XGBoost:** actual boosted-tree challenger via its sklearn-compatible estimator, when available. Fixed class ordering and normalized probability outputs require checks. Thread counts and tree/trial budgets must be bounded on shared CPU. [Official Python API](https://xgboost.readthedocs.io/en/stable/python/python_api.html). This dependency does not turn the separate NumPy educational tree demonstration into XGBoost.
- **LightGBM:** a distinct boosted-tree challenger through `LGBMClassifier`/`LGBMRegressor`. Early stopping and time-ordered validation must not consume the final holdout. Thread and leaf constraints matter on small samples and shared hardware. [Official Python API](https://lightgbm.readthedocs.io/en/stable/Python-API.html).
- **SciPy:** distributions, statistical tests, optimization and numerical support. A test's assumptions and multiple-comparison context determine its meaning; a p-value is not an alpha probability. [Official scipy.stats reference](https://docs.scipy.org/doc/scipy/reference/stats.html).
- **statsmodels:** genuine ARIMA estimation where enabled, separate from the constrained educational `ARIMA(p,1,0)` routine. Convergence, residual diagnostics and forecast uncertainty need checks. [Official ARIMA API](https://www.statsmodels.org/stable/generated/statsmodels.tsa.arima.model.ARIMA.html).
- **Optuna:** bounded hyperparameter studies, using a chronological validation objective and seeded sampler. The final holdout must remain untouched by trial selection. With `storage=None`, studies are in memory and are not persistent. [Official create_study API](https://optuna.readthedocs.io/en/stable/reference/generated/optuna.create_study.html).
- **mlflow-skinny** (import `mlflow`): run IDs, parameters, scores and version metadata through the lightweight tracking client. Use a separate local temporary store per run and export selected metadata in the UI. This is ephemeral tracking, not a deployed MLflow server or persistent cross-session history. No user-controlled remote tracking URI or credentials are needed. The [official tracking guide](https://mlflow.org/docs/latest/ml/tracking/) describes runs, parameters, metrics and artifacts; exact skinny-package backend support must be verified in the installed environment.
- **SHAP:** bounded explanations of supported fitted tree models. TreeExplainer documents multiple assumptions about dependent features, and raw outputs need not be probabilities. Attribution explains model output under the chosen background/perturbation convention; it does not establish causality. Fit or select the background using training data and explain only a small sample to bound CPU/memory. [Official TreeExplainer API](https://shap.readthedocs.io/en/latest/generated/shap.TreeExplainer.html).
- **PyTorch, optional:** a genuine small multilayer perceptron using `torch.nn`, autograd and an optimizer if installed and explicitly enabled. A basic MLP is not TFT, PPO or DeepSurv. Restrict epochs, hidden width and CPU threads; disclose optional availability. [Official Sequential API](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Sequential.html).

TensorFlow is omitted because adding a second deep-learning framework serves no present model requirement. Qiskit is omitted because no quantum computation problem or defensible quantum advantage has been specified. These omissions avoid dependency weight without implying those frameworks are generally unsuitable.

## Interpretation and security limits

No library eliminates leakage, market nonstationarity, unmodeled trading costs or multiple-testing bias. Synthetic demos establish behavior under chosen simulated premises only. Black-Scholes pricing is risk-neutral; ordinary return probabilities are physical-measure estimates. Kelly sizing requires a payoff/return distribution and exposure constraints, not only a directional probability.

Accept only bounded data uploads. Do not deserialize untrusted models, evaluate expressions, execute scripts, fetch arbitrary user URLs, expose local paths or put secrets into logs/exports. Temporary output cleanup and session isolation require actual implementation checks. Exports may contain uploaded data summaries; users should review them before sharing. Exact executed test outcomes belong in the verification report, not in dependency documentation.
